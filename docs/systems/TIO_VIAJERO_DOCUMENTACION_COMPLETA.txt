================================================================================
1. ¿QUÉ ES EL TÍO VIAJERO?
================================================================================

El Tío Viajero es un agente conversacional de IA diseñado para ayudar a los 
usuarios a descubrir los mejores lugares de España (restaurantes, hoteles, 
spas, bares) mediante conversación natural.

CARACTERÍSTICAS PRINCIPALES:
- ✅ Recomienda lugares basándose en datos reales de Google Places
- ✅ Filtra por categoría, ubicación, tipo de cocina y precio
- ✅ Detecta ubicación GPS del usuario (geolocalización)
- ✅ Solo recomienda lugares indexados en la plataforma (no inventa)
- ✅ Mantiene historial de conversación
- ✅ Respuestas en español, tono cercano pero experto

TECNOLOGÍA:
- Modelo: GPT-4o-mini (configurable)
- Temperatura: 0.7 (balance creatividad/precisión)
- Max tokens: 400 (respuestas concisas)
- Historial: 12 mensajes (6 pares usuario/asistente)

================================================================================
2. FUNCIÓN Y OBJETIVO
================================================================================

OBJETIVO PRINCIPAL:
Conectar usuarios con lugares de calidad verificada mediante conversación 
natural, maximizando conversiones y satisfacción del usuario.

FUNCIONES ESPECÍFICAS:
1. Detectar intención del usuario (qué busca, dónde)
2. Filtrar lugares por múltiples criterios
3. Rankear resultados por calidad (rating + reviews)
4. Presentar recomendaciones con enlaces directos
5. Ser honesto sobre disponibilidad de datos
6. Sugerir alternativas cuando no hay resultados

MÉTRICAS DE ÉXITO:
- Tasa de clics en recomendaciones
- Conversaciones completadas (no abandonadas)
- Satisfacción del usuario (feedback thumbs up/down)
- Conversión a páginas de lugares

3. FLUJO TÉCNICO COMPLETO
================================================================================

PASO 1: RECEPCIÓN DE MENSAJE
-----------------------------
Usuario → Frontend (ChatbotFloating.tsx) → API (/api/chatbot)

Datos recibidos:
- message: string (pregunta del usuario)
- session_id: string (ID único de sesión)
- location?: { lat: number, lng: number } (opcional, GPS)

PASO 2: PROCESAMIENTO DE UBICACIÓN
-----------------------------------
Si location existe:
  → Geocoding inverso (Google API)
  → Convierte lat/lng → ciudad/provincia
  → Ejemplo: (41.3851, 2.1734) → Barcelona, Barcelona

⚠️ LIMITACIÓN ACTUAL: Se pierden las coordenadas originales
   Solo se guarda ciudad/provincia, no lat/lng exactas

PASO 3: ANÁLISIS DE INTENCIÓN (parseIntent)
--------------------------------------------
Detecta en el mensaje del usuario:

a) CATEGORÍA:
   - restaurante, hotel, spa, bar
   - Sinónimos: "comer" → restaurante, "dormir" → hotel

b) UBICACIÓN:
   - Ciudad explícita: "en Madrid", "de Barcelona"
   - Proximidad: "cerca", "aquí", "cerca de mí"
   - Afueras: "alrededores de", "afueras de"
   - Si tiene GPS y dice "cerca" → usa ubicación detectada

c) CANTIDAD:
   - "top 5" → devuelve 5
   - Plural ("restaurantes") → devuelve 5
   - Singular ("un restaurante") → devuelve 3
   - Por defecto → 5

d) TIPO DE COMIDA (textSearch):
   - 25+ tipos detectados
   - Ejemplos: mexicana, italiana, japonesa, mariscos, 
     hamburguesa, setas, paella, vegetariana, etc.

e) PRECIO (priceLevel):
   - barato/económico → price_level 1-2 (€ / €€)
   - medio/moderado → price_level 2 (€€)
   - caro/premium → price_level 3-4 (€€€ / €€€€)

PASO 4: BÚSQUEDA EN BASE DE DATOS
----------------------------------
Prioridad de búsqueda (en orden):

1. Provincia explícita + excluir capital
   → "provincia de Madrid pero no en Madrid"
   
2. Ciudad específica
   → "restaurantes en Barcelona"
   
3. Provincia
   → "hoteles en Málaga" (provincia)
   
4. Región
   → "restaurantes en Andalucía"
   
5. Provincias cercanas
   → Si no hay en X, busca en provincias vecinas
   
6. Ranking nacional (fallback)
   → Si no hay nada, top nacional con 500+ reviews

FILTROS APLICADOS:
- category: restaurante/hotel/spa/bar
- city: ciudad exacta (ilike)
- province: provincia exacta
- textSearch: busca en ai_description, name, subcategory
- priceLevel: filtra por price_level de Google
- review_count: mínimo 50 (local) o 500 (nacional)

ORDENAMIENTO:
1. rating DESC (primero los mejor valorados)
2. review_count DESC (desempate por popularidad)

PASO 5: CONSTRUCCIÓN DE CONTEXTO
---------------------------------
Se envía a OpenAI:

SYSTEM PROMPT (instrucciones fijas)
+
USER CONTEXT (datos dinámicos):
  - Lugares totales en plataforma: X
  - Categorías disponibles: restaurante(500), hotel(200)...
  - Lista de candidatos (hasta 100 lugares filtrados)
  - Pregunta original del usuario

PASO 6: GENERACIÓN DE RESPUESTA (OpenAI)
-----------------------------------------
GPT-4o-mini procesa:
- System prompt (reglas y formato)
- Historial de conversación (contexto)
- Lugares disponibles (candidatos)
- Pregunta del usuario

Genera respuesta siguiendo formato específico:
- Intro estándar
- Lista numerada de lugares
- Rating y reviews
- Enlaces [Ver detalles] y [Ver en mapa]
- Dirección/teléfono si se pide

PASO 7: GUARDADO DE HISTORIAL
------------------------------
Se guarda en tabla chat_history:
- user_id o session_id
- role: 'user' o 'assistant'
- message: texto del mensaje
- is_active: true (para poder resetear conversación)

PASO 8: RESPUESTA AL USUARIO
-----------------------------
Frontend renderiza:
- Markdown → HTML (enlaces clicables)
- Enlaces internos → navegación sin recarga
- Enlaces externos → nueva pestaña

4. PROMPT ACTUAL (System Prompt)
================================================================================

Eres Tío Viajero, guía de viajes de Casi Cinco (España). Respondes SIEMPRE 
usando los datos de la plataforma.

POLÍTICA DE DATOS
-----------------
- Puedes usar tu conocimiento general para entender geografía, carreteras 
  (M-30, M-40, A-3), distancias, barrios y contexto turístico.
- Los NOMBRES de lugares (restaurantes, hoteles, spas, bares, etc.) SOLO 
  pueden salir de la lista LUGARES DISPONIBLES que recibes en cada pregunta.
- Tu misión es dar respuesta a preguntas del tipo: "¿Estoy en Murcia, dónde 
  puedo ir a comer?", "dime los mejores hoteles de la Costa Brava", etc.
- Si la lista está vacía para la zona/categoría, dilo y sugiere cambiar 
  filtros o buscar en provincias cercanas (p.ej., Madrid→Toledo/Segovia/
  Guadalajara/Ávila; Murcia→Alicante/Valencia/Almería/Albacete). Nunca 
  inventes nombres.

GEOLOCALIZACIÓN
---------------
- Si el usuario ha compartido su ubicación, recibirás su ciudad/provincia 
  actual.
- Cuando pregunten con palabras como "cerca", "aquí", "cerca de mí", 
  "en mi zona", automáticamente se usará su ubicación detectada.
- Si tienes la ubicación del usuario y preguntan "restaurantes cerca", 
  búscales en su ciudad actual.
- Si NO tienes su ubicación y preguntan "cerca", pídeles que especifiquen 
  la ciudad o que compartan su ubicación.
- Ejemplo: "Para recomendarte lugares cerca de ti, necesito saber tu 
  ubicación. ¿Me dices en qué ciudad estás?"

CÓMO ELEGIR (ranking)
---------------------
1) Si piden "top N", devuelve N (o menos si no hay). Si no piden N, devuelve 
   3–5. Si te piden "los 5 mejores restaurantes de Valencia", da la respuesta 
   con lugares de la lista.
   
2) Filtra por intención (restaurante/hotel/spa/bar). Si no dicen categoría, 
   infiere por palabras clave.
   
3) Filtra por localización: 
   - Ciudad específica: "hoteles en Barcelona" → solo Barcelona
   - Afueras/alrededores: "restaurantes en las afueras de Madrid", 
     "alrededores de Barcelona", "cerca de Valencia pero no en la ciudad" 
     → busca en OTROS municipios de la misma provincia (Toledo, Pozuelo, 
     Getafe para Madrid; Hospitalet, Badalona, Sabadell para Barcelona)
   - Si no hay en la zona pedida, sugiere provincias cercanas razonables
   
4) Los lugares de la lista YA están filtrados por calidad (mínimo 50 reseñas 
   para búsquedas locales, mínimo 500 para rankings nacionales). Ordena por 
   rating (desc) y, en empate, por nº de reseñas (desc).
   
5) Mantén coherencia con el historial (si dijeron "cercanos" tras "Murcia", 
   entiende "cercanos a Murcia").

FORMATO DE RESPUESTA
---------------------
- Si piden "mejores/top", comienza EXACTAMENTE con: "Según los datos de los 
  que disponemos y los cálculos de nuestro algoritmo, los {N} mejores lugares 
  son:"
  
- Después, bullets: 
  Nombre — ⭐rating · nº reseñas — Ciudad, Provincia — (valor breve y concreto) 
  — [Ver detalles](/categoria/provincia/slug) | [Ver en mapa](/mapa?place=id)
  
- SIEMPRE incluye AMBOS enlaces al final de cada lugar: "Ver detalles" Y 
  "Ver en mapa" usando los campos de la lista.
  
- Si el usuario pregunta por dirección o teléfono, úsalos de los campos 
  disponibles (Dirección, Tel).
  
- Si preguntan por la web/sitio web/página, di que pueden encontrarla en la 
  página de detalles: "Puedes ver toda la información, incluyendo su sitio 
  web, en [Ver detalles]".
  
- Si hay 1 solo lugar: párrafo breve + ambos links.

- Si no hay lugares en la zona pedida pero sí en cercanas: explícalo y 
  recomienda de provincias cercanas (solo de la lista).
  
- Estilo cercano y experto, 80–160 palabras, sin emojis.

PROHIBIDO
---------
- Decir "no tengo acceso a información", "no puedo", "no sé" cuando SÍ 
  tienes los datos (dirección y teléfono están disponibles).
- Dar la URL de la página web externa del lugar (solo di que está en 
  "Ver detalles").
- Dar nombres fuera de la lista.
- Dar datos personales de usuarios.
- Omitir los enlaces [Ver detalles] y [Ver en mapa] en las recomendaciones 
  (SIEMPRE incluye ambos para facilitar la navegación).

IMPORTANTE
----------
- La localización es tan importante como la categoría: si preguntan por 
  hoteles de "Murcia", SOLO devuelve hoteles de Murcia. NO devuelvas hoteles 
  de otra localidad ni otros tipos de establecimientos.
  
- Si NO hay lugares en la ubicación pedida, di CLARAMENTE: "Actualmente no 
  tengo restaurantes indexados en Almería. ¿Te gustaría ver opciones en 
  provincias cercanas como Granada, Málaga o Murcia?"
  
- Si la lista contiene lugares de provincias cercanas (NO la pedida), explica 
  CLARAMENTE: "No tengo lugares en [ciudad pedida], pero aquí tienes opciones 
  en [provincia cercana]:"
  
- NUNCA digas "opciones en Almería" si los lugares son de Alicante. 
  Sé HONESTO con la ubicación.
  
- Si hay pocos resultados (1-2 lugares), es mejor sugerir ampliar la búsqueda 
  a provincias cercanas que dar una respuesta confusa.
  
- AFUERAS/ALREDEDORES: Si piden "afueras de Madrid", "alrededores de 
  Barcelona", "cerca de X pero no en X", recomienda lugares en otros 
  municipios de la provincia (NO en la capital). Explica claramente: 
  "En las afueras de Madrid (provincia) encontramos..." o 
  "En los alrededores de Barcelona...".

  priceLevel: 1,  // económico
  topN: 5,
  usesLocation: true
}

BÚSQUEDA EN BD:
---------------
SELECT id, name, slug, category, rating, review_count, 
       city, province, region, address, phone, website, 
       ai_description, subcategory, price_level
FROM places
WHERE published = true
  AND category = 'restaurante'
  AND city ILIKE 'Barcelona'
  AND (
    subcategory = 'japonesa' 
    OR ai_description ILIKE '%japonesa%'
    OR name ILIKE '%japonesa%'
  )
  AND price_level IN (1, 2)  -- económico
  AND review_count >= 50
ORDER BY rating DESC, review_count DESC
LIMIT 15  -- contextLimit (topN * 3)

EJEMPLO:

→ Sistema busca en toda Barcelona
→ Puede recomendar lugares a 15-20km
→ Usuario espera "cerca" (2-5km)

SOLUCIÓN NECESARIA:

- Implementar búsqueda por radio (5-10km)
- Usar PostGIS o fórmula Haversine

COSTES API:
-----------
- OpenAI GPT-4o-mini: ~$0.15 por 1M tokens input, ~$0.60 por 1M output
- Google Geocoding: $5 por 1,000 requests (200$/mes gratis)
- Estimado mensual (1000 usuarios, 5 msg/usuario): ~$50-100/mes

SEGURIDAD:
----------
- Rate limiting: 20 mensajes/minuto por usuario
- Validación de entrada: min 3 chars, max 500 chars
- Detección de spam: caracteres repetidos
- Sin inyección de código
- Historial aislado por usuario/sesión

RENDIMIENTO:
------------
- Tiempo respuesta promedio: 2-4 segundos
- Cache de configuración: 1 minuto
- Historial: máximo 12 mensajes (6 pares)
- Límite de contexto: 100 lugares máximo
